# Sentimena — IDX Stock Sentiment Analysis & Prediction (Skripsi)

Laravel app + Python ML backend. Predicts IDX stock direction from technical + news-sentiment
features, with a Decision Support System (DSS) layered on top. Built as a thesis project — honest,
evidence-based findings (including negative results) matter more than polished numbers.

## Pipeline (5 stages — mental model for almost everything here)

```
Berita (news ingest) → Analisis Sentimen (rule-based + fine-tuned IndoBERT) →
Fitur Gabungan (technical + sentiment) → Model Prediksi (V6A/V6B, RF/LogReg) → DSS
```

- **V6A** (`model_technical_v6a.joblib`): RandomForest, technical-only, 10 official tickers.
- **V6B** (`model_technical_sentiment_v6b.joblib`): LogisticRegression, technical+sentiment.
- BUMI/DEWA have separate, dedicated volatile-stock models — not part of V6A/V6B.
- All model claims must be backed by **walk-forward out-of-sample validation**
  (`build_folds`/`evaluate_predictions`/`mean_metrics` in `quant/train_prediction_models.py`), not
  naive backtests. A "best config found by trying many settings" is data-snooping — avoid it.

## Tech stack

- **Backend**: Laravel 13, PHP 8.3, MySQL (`sentimena_dashboard`, no queue/Redis — plain sync).
- **ML serving**: Python (FastAPI, `quant/prediction_api.py` + `quant/sentiment_api.py`), invoked
  by Laravel via `Symfony\Component\Process\Process` or HTTP. `PYTHON_BINARY` env var (default
  `python3`) controls the interpreter used by retrain commands.
- **Frontend**: Blade + Alpine.js + Tailwind, Vite build. No SPA framework.
- **Tests**: plain PHPUnit (not Pest) — `php artisan test`. `vendor/bin/pint` for PHP style.

## Directory map

- `app/Console/Commands/` — 30 artisan commands; scheduled ones are the backbone (news fetch,
  sentiment reanalyze, fundamentals sync, retrain-volatile, retrain-production, auto-recover-gap).
- `app/Services/{Analytics,MarketData,News,Prediction,Research,Sentiment,Stocks,Trading}/` —
  domain services. `ResearchPredictionFeatureService` is the canonical feature builder used by
  both training (via CSV export) and live serving.
- `quant/` — ~176 Python scripts. Mix of production trainers (`train_production_models.py`,
  `train_volatile_stock_models.py`) and one-off research/experiment scripts (`run_v6a_*.py`,
  `run_v6b_*.py`, etc.) whose *results* are frozen findings, not code meant to be re-run casually.
- `data/stocks/{TICKER}.csv` — static historical OHLCV snapshots (source of truth for model
  training features, decoupled from the live `stock_prices` DB table — DB is fresher but training
  doesn't read it directly; check `data/stocks/*.csv` freshness before assuming a retrain
  captured recent price action).
- `output/prediction_research/` — generated datasets/reports. Large CSVs, regenerated by
  `prediction:export-research-dataset` and the retrain commands; not meant to be read whole.
- `storage/app/prediction/` — production model artifacts + `retrain_history.jsonl` (append-only
  log read by the `/analytics` "Status Retrain Model" table) + `archive/` (auto-backups before
  every promotion) + `candidates/` (rejected/pending retrains).
- `routes/console.php` — single source of truth for the scheduler; if a command should run
  automatically, its entry must be here (there is no separate cron config).
- `plan.md` — running execution log of this thesis session's audit/fixes, per phase. Check it
  before assuming something is broken or unfixed; append to it (don't rewrite) when documenting a
  new finding.

## Conventions / rules specific to this repo

- **Never claim a metric without walk-forward OOS numbers.** Static/frozen baselines
  (`official_baseline` in model metadata) are historical provenance, not something to re-gate
  against — see `retrain_evaluation` in model metadata for the field that's actually recomputed
  fresh each retrain.
- **Retrain commands are safety-gated by design**: `prediction:retrain-volatile` (BUMI/DEWA) and
  `prediction:retrain-production` (V6A/V6B) never overwrite a production model that regresses
  macro-F1 by more than 0.05 — they save a `*_candidate.joblib` instead. Don't bypass this gate
  manually; if a model needs forcing through, that's a decision to discuss, not a default.
- **MySQL is manual, not a LaunchDaemon** — this was explicitly decided (session tradeoff:
  simplicity over always-on). `news:auto-recover-gap` (every 30 min) exists specifically to backfill
  news gaps caused by MySQL/scheduler being off, so an outage self-heals once it's back up.
- **`source='seed'` rows in `stock_prices`** are leftover synthetic data — filter them out
  (`WHERE source <> 'seed'`) in any query that must reflect real market data.
- Don't build backtest/trading-signal features on top of a metric that hasn't itself been
  OOS-validated — this project has already discarded multiple features (buying-pressure, old DSS
  weight optimization) that looked promising pre-validation and failed OOS. Validate first.

## Testing

- `php artisan test` — full suite (400+ tests). Run before considering any backend change done.
- Feature tests that touch Python training scripts fake the subprocess via
  `PYTHON_BINARY=php` + a throwaway PHP script mimicking the real script's argv contract (see
  `RetrainVolatilePredictionModelsCommandTest` / `RetrainProductionPredictionModelsCommandTest` for
  the pattern) — don't invoke real sklearn training in tests, it's slow and non-deterministic.
- Commands that read real historical price series can use `Stock::factory()->create(['code' =>
  'BBCA'])` — the real CSV at `data/stocks/BBCA.csv` already has enough history, no need to
  fabricate synthetic OHLCV rows.

## Do / Don't

- **Do** read `plan.md` for recent findings before re-investigating something that sounds familiar.
- **Do** keep negative/failed findings in `plan.md` rather than deleting them — they're thesis
  evidence, not clutter.
- **Don't** run `git add -A` — stage files explicitly (this repo mixes generated CSVs, logs, and
  real source; a blind add easily sweeps in multi-MB regenerated datasets).
- **Don't** assume `output/prediction_research/*.csv` or `storage/app/prediction/*.joblib` changes
  are safe to discard without checking `git diff`/`git log` first — some are checked-in research
  provenance, not disposable build output.
